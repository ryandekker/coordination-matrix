# Workflow Review Documents

How to create rich review content for manual approval steps in workflows.

## Overview

When a workflow reaches a manual (human review) step, the system can automatically create and attach a formatted document for the reviewer. This document renders inline in the review UI with full markdown support, including mermaid diagrams, tables, and links.

The pattern is: **code step generates markdown** -> **manual step auto-attaches it as a document** -> **reviewer sees rich content instead of raw JSON**.

## How It Works

### 1. Auto-Attach Document from Input

When a manual step is created, the workflow engine calls `autoAttachDocumentFromInput()`. It looks for content in the previous step's output at these paths (in order):

- `output.result.draft`
- `output.result.content`
- `output.result.document`

If found, it creates a `Document` record with:
- `status: 'review'`
- `type: 'output'`
- `metadata.autoGenerated: true`
- Linked to the manual task via `relatedTaskIds`

### 2. ManualReviewPanel Rendering

The frontend `ManualReviewPanel` detects attached documents with `autoGenerated: true` or `status: 'review'` and renders them inline with full markdown support. The raw JSON from the previous step is still available as a collapsible "Raw Step Data" section.

### 3. Dynamic Task Summary

When a manual step receives `inputPayload.output.result.summary`, that string is used as the task's `summary` field instead of the static step description. This makes the task card more informative.

## Code Step Return Format

To generate a review document from a code step preceding a manual step:

```javascript
return {
  result: {
    title: 'Review: My Workflow',      // Required: document title
    content: '# Markdown content...',   // Required: markdown body
    summary: 'Brief summary',           // Optional: task card summary
  },
  // These surface as clickable links in the Produced Assets panel:
  workflowId: '6abc...def',            // Optional: link to workflow definition
  workflowName: 'My Workflow',         // Optional: display name for workflow link
};
```

### Supported Markdown Features

The `content` field supports:
- Standard markdown (headers, lists, bold/italic, blockquotes)
- GitHub Flavored Markdown (tables, strikethrough)
- Mermaid diagrams (` ```mermaid ` code blocks rendered as interactive SVG)
- Links (both internal app links and external URLs)

### Mermaid Diagram Example

```javascript
const lines = ['flowchart TD'];
for (const step of workflowSteps) {
  const shapes = { agent: ['([', '])'], manual: ['{{', '}}'], code: ['[/', '/]'], decision: ['{', '}'] };
  const shape = shapes[step.stepType] || ['[', ']'];
  lines.push(`    ${step.id}${shape[0]}"${step.name}"${shape[1]}`);
}
for (const step of workflowSteps) {
  for (const conn of step.connections || []) {
    const label = conn.label || conn.condition || '';
    lines.push(label
      ? `    ${step.id} -->|${label}| ${conn.targetStepId}`
      : `    ${step.id} --> ${conn.targetStepId}`
    );
  }
}
const mermaidDiagram = lines.join('\n');

// Include in markdown:
const content = `## Workflow Diagram\n\n\`\`\`mermaid\n${mermaidDiagram}\n\`\`\``;
```

## Produced Assets (Linkable Fields)

The `ProducedAssetsPanel` automatically extracts clickable links from task data. For manual tasks, it scans both the task's own output and the `inputPayload` from the previous step.

### Fields That Generate Links

| Location | Field | Asset Type | UI Link |
|----------|-------|-----------|---------|
| `output.result.workflowId` | workflowId + workflowName | Workflow | `/workflows?workflowId=...` |
| `output.workflowId` | workflowId + workflowName | Workflow | `/workflows?workflowId=...` |
| `output.result.externalUrl` | externalUrl + externalTitle | External | URL directly |
| `inputPayload.output.workflowId` | (same) | Workflow | (same) |
| `inputPayload.output.result.workflowId` | (same) | Workflow | (same) |
| Task's `spawnedWorkflowRunId` | — | Workflow Run | `/workflow-runs?id=...` |
| Task's `workflowRunId` (manual tasks) | — | Workflow Run | `/workflow-runs?id=...` |

### Adding New Asset Types

To surface a new type of link, add extraction logic in `frontend/src/components/tasks/task-modal/produced-assets-panel.tsx` in the `extractAssetsFromTask()` function. Follow the existing pattern of checking metadata paths and pushing to the `assets` array.

## Code Step API Access

Code steps can fetch data from the platform API to enrich review documents:

```javascript
// codeConfig:
{
  code: `
    // Fetch workflow definition for diagram
    const res = await fetch(apiUrl + '/workflows/' + workflowId, {
      headers: { 'X-API-Key': apiKey, 'Content-Type': 'application/json' }
    });
    const wf = (await res.json()).data;
    // Build mermaid diagram from wf.steps...
  `,
  packages: ['node-fetch'],
  variables: [
    { name: 'apiUrl', path: '_apiUrl' },
    { name: 'apiKey', path: '_apiKey' },
  ],
}
```

System variables available:
- `_apiUrl` — Platform API base URL (e.g., `https://cm.hcizero.com/api`)
- `_apiKey` — System API key for authenticated requests
- `_workflowRunId` — Current workflow run ID

## Complete Example: Prepare-Review Step

See `scripts/workflows/deploy-wc-v2.mjs`, step `prepare-review` for a production example that:

1. Walks `_stepLog` to extract phase results from each completed step
2. Fetches the created workflow via API to get the full step definitions
3. Builds a mermaid flowchart from the workflow's steps and connections
4. Generates a markdown document with:
   - Original request (blockquoted)
   - Quick links to the workflow and workflow run
   - Mermaid diagram of the created workflow
   - Step summary table
   - Phase-by-phase results with status icons
   - E2E test results
5. Returns `{ result: { title, content, summary }, workflowId, workflowName }`

The downstream `human-approval` step then:
- Gets the document auto-attached
- Shows it inline with markdown rendering
- Shows workflow/run links in the Produced Assets panel
- Uses the dynamic summary on the task card
